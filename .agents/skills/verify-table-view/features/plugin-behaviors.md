# Plugin behavior across table views

Each property type supplies data semantics through table-hook and controls through its paired table-view adapter. A property remains sortable, groupable, filterable, and calculable according to that plugin when the layout changes. Editing capability alone does not describe a plugin.

## Sub-features

### Built-in capabilities

The [hook exports](../../../../packages/table-hook/src/plugins/index.ts) and [default UI pairs](../../../../packages/table-view/src/plugins/index.ts) define these 12 plugins. Direction labels below describe row sorting; automatic group sorting is a separate setting. The shared accessor places values considered empty by the plugin last in either row-sort direction. Grouping collects those values into a null bucket. [Shared accessors](../../../../packages/table-hook/src/table-contexts/use-table-view.tsx).

| Plugin ID          | Value and emptiness                                                                             | Row sorting                                                                             | Group using and heading                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `title`            | String; blank after trimming is empty                                                           | A→Z / Z→A                                                                               | Exact or Alphabetical initial; plain text                                   |
| `text`             | String; blank after trimming is empty                                                           | A→Z / Z→A                                                                               | Exact or Alphabetical initial; plain text                                   |
| `email`            | String; blank after trimming is empty                                                           | A→Z / Z→A                                                                               | Exact or Alphabetical initial; plain text                                   |
| `phone`            | String; blank after trimming is empty                                                           | A→Z / Z→A, lexically rather than numerically                                            | Exact or Alphabetical initial; plain text                                   |
| `url`              | String; blank after trimming is empty                                                           | A→Z / Z→A                                                                               | Exact or Alphabetical initial; plain text                                   |
| `number`           | Numeric string or null; blank/nonfinite is empty for sorting, filtering, and numeric aggregates | Low→high / High→low                                                                     | Every 1/10/100/1000; formatted interval                                     |
| `checkbox`         | Boolean; false counts as empty                                                                  | Checked→unchecked / Unchecked→checked labels; unchecked remains last in both directions | Value only; checkbox indicator beside property name; Manual group sort only |
| `select`           | Option name or null; null is empty                                                              | Ascending / Descending by name                                                          | Value only; configured option tag                                           |
| `multi-select`     | Ordered option-name array; empty array is empty                                                 | Ascending / Descending by **first selected name**                                       | Value only, using **first selected name**; one group per row                |
| `date`             | Date object with start, optional end/range/time fields; missing start is empty                  | Old→new / New→old by start                                                              | Relative/Day/Week/Month/Year; date-aware label                              |
| `created-time`     | Read-only `row.createdAt`; stored cell is null, never considered empty                          | Old→new / New→old                                                                       | Same date methods and labels                                                |
| `last-edited-time` | Read-only `row.lastEditedAt`; stored cell is null, never considered empty                       | Old→new / New→old                                                                       | Same date methods and labels                                                |

Headings use the corresponding [UI plugin](../../../../packages/table-view/src/plugins/index.ts), including `(Empty)` for text, option, number, and date empty buckets. Checkbox uses an unchecked indicator instead.

### Sorting and grouping semantics

- `plugin-methods`: hook plugins register sorting/grouping method IDs, defaults, comparators, grouping functions, and direction labels. Resolution uses the selected ID, then the plugin default, then its first method. Legacy row comparison/group conversion are fallbacks for plugins without the corresponding method collection. Custom-plugin contracts live in [types](../../../../packages/table-hook/src/plugins/types.ts) and [method resolution](../../../../packages/table-hook/src/methods.ts).
- `plugin-row-sort`: the Sort menu chooses a property and direction, without a separate method picker. Adding/replacing a rule or using header Sort selects that plugin's default method. Row-sort direction/priority uses internal state; selecting its method can emit `view.plugin_sorting_method.change`. [Sort menu](../../../../packages/table-view/src/menus/sort-menu.tsx), [view actions](../../../../packages/table-hook/src/features/menu.ts).
- `plugin-group-method`: Group using appears only when the plugin provides multiple methods. Number intervals use `floor(value / interval) * interval`, including negative numbers; the displayed interval's upper boundary is exclusive. Text Alphabetical groups by initial. Date grouping uses the property's timezone and the consumer's week start; Relative is time-dependent. [Grouping functions](../../../../packages/table-hook/src/fns/grouping.ts), [number methods](../../../../packages/table-hook/src/plugins/number/plugin.ts), [group editor](../../../../packages/table-view/src/menus/edit-group-menu.tsx).
- `plugin-group-sort`: Sort groups offers Manual and the selected eligible comparator's directions. Eligibility requires comparable-value conversion and comparison, with group sorting enabled; a legacy row comparator alone is insufficient. Empty groups stay last. Dragging groups switches automatic order to Manual. Checkbox exposes Manual only. [Method eligibility](../../../../packages/table-hook/src/methods.ts), [group ordering](../../../../packages/table-hook/src/features/grouping.ts).
- `plugin-options-order`: select option-menu order, row sorting, and group ordering are separate. Sorting/grouping uses names, not the order in `config.options`; multi-select uses the first stored selection, not every tag. Renaming/deleting options changes referring cell values and therefore derived order/membership. [Select methods](../../../../packages/table-hook/src/plugins/select/plugin.ts), [option reducer](../../../../packages/table-view/src/plugins/select/select-config-reducer.ts).

### Filtering, search, and calculation

| Plugin family                      | Filter behavior                                                                                                       | Calculation choices                                                         |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Title/Text/Email/Phone/URL         | Case-insensitive equals/not equal, contains/not contains, starts/ends with; trimmed empty checks                      | All, Values, Unique, Empty, Not empty; empty/nonempty percentages           |
| Number                             | Equals/not equal, greater/less than, inclusive comparisons, empty/nonempty; nonfinite values fail numeric comparisons | Generic counts plus Sum/Average/Median/Minimum/Maximum/Range                |
| Select                             | Is/Is not by exact option name, empty/nonempty                                                                        | Generic counts and percentages                                              |
| Multi-select                       | Contains requires all chosen options; Does not contain requires all absent; empty/nonempty                            | Generic counts and percentages; Values/Unique count individual option names |
| Checkbox                           | Is checked / Is unchecked, with no operand                                                                            | All/Checked/Unchecked; checked/unchecked percentages                        |
| Date/Created time/Last edited time | Equals/Before/After/On or before/On or after/Between/Relative to today; empty/nonempty                                | Generic counts plus Earliest date/Latest date/Date range                    |

These operators and calculations are defined by the plugin files linked above, not by editor widgets. Their non-obvious contracts are:

- `plugin-counting`: Values/Unique convert through `plugin.toValue`, split comma-separated text, and trim/discard empty pieces. Unique is case-sensitive. Not empty counts populated rows through `isEmpty`. For Tags `[Frontend]`, `[]`, `[Frontend, Backend]`, Values is 3, Unique is 2, Not empty is 2. Comma tokenization also applies to text/contact values. [Counting functions](../../../../packages/table-hook/src/fns/calculating.ts), [generic methods](../../../../packages/table-hook/src/plugins/utils.ts), [aggregation bridge](../../../../packages/table-hook/src/methods.ts).
- `plugin-numeric-calculation`: numeric aggregates ignore blank/nonfinite inputs, and every numeric aggregate, including Sum, renders empty when none remain. Results use current Number formatting; formatting does not change stored inputs. Generic Values/Unique conversion is a separate path. [Number calculations](../../../../packages/table-hook/src/plugins/number/plugin.ts).
- `plugin-date-comparison`: date-only filters compare timezone-local calendar days; Include time compares timestamps. Between is inclusive and tests the cell's **start**, not range overlap. Relative to today resolves a day/week/month/year offset to one exact local day, not an entire interval. Active relative filters refresh on minute boundaries. [Date filtering](../../../../packages/table-hook/src/plugins/date/plugin.ts), [refresh](../../../../packages/table-hook/src/table-contexts/use-table-view.tsx).
- `plugin-date-calculation`: Earliest uses minimum valid start; Latest uses maximum valid end or start; Date range measures the span between these global boundaries. No valid starts produces empty output. Date-only spans use calendar days; timed spans can show days/hours/minutes. Generated timestamps use the same methods with time included. [Date aggregation](../../../../packages/table-hook/src/fns/calculating.ts), [date formatting](../../../../packages/table-hook/src/plugins/date/utils.ts).
- `plugin-search`: search matches `toTextValue`, which can differ from rendered formatting. Number uses its stored string, multi-select joins names with commas, checkbox uses `✅` or empty text. Dates use full/24-hour formatting with the timezone captured by the plugin factory, rather than the property's current display format. [Search pipeline](../../../../packages/table-hook/src/features/filtering.ts), [date text conversion](../../../../packages/table-hook/src/plugins/date/plugin.ts).
- `plugin-derived-results`: filter changes and cell/bulk edits recompute row order, group membership, and calculations. Footer calculations use filtered pre-grouped rows, not just expanded or visible groups. [Calculation inputs](../../../../packages/table-hook/src/lib/utils.ts).

### UI adapters and cross-feature effects

- `plugin-ui-pair`: each hook plugin ID needs one matching UI adapter; duplicate IDs, missing adapters, and orphan adapters are errors. Cell rendering is required; bulk/config/group-label rendering is capability-specific. See [registry](../../../../packages/table-view/src/plugins/registry.ts) and [editing/resource contracts](editing-and-resources.md).
- `plugin-config`: Number formats affect cell, interval-heading, and calculation presentation; date configuration affects date labels/calculations/filter comparison; select names/colors affect cells and group tags. Type conversion keeps the property ID and converts values/configuration. Recheck applicable methods after conversion; unsupported method IDs fall back according to method resolution, while an unknown calculation ID produces no calculation. See [properties](properties.md).
- `plugin-bulk`: title and generated timestamps have no bulk editor; other built-ins do when visible. Bulk drafts start from plugin defaults, not a common selected value; checkbox instead toggles the selected set. See [selection and row actions](selection-and-row-actions.md).
- `plugin-layout`: Table/List/Board/Timeline share plugin sorting/grouping and heading renderers. Compact List/Board cells omit many empty values, while unchecked Checkbox stays visible. Only editable `date` properties qualify for Timeline by; generated timestamp plugins can still sort/group/filter/calculate. Timeline shows title and its selected date track, with other properties available in row detail. See [layouts and row views](layouts-and-row-views.md).

## How to get to it (user POV)

- Create or change a property type from a header or **Settings → Edit properties → New property**; inspect its configuration from the header's **Edit property** submenu or a row-detail property menu.
- Use toolbar/header **Sort** and **Filter**, header/footer **Calculate**, or **Settings → Group**. The property type determines available operators, direction labels, grouping methods, and calculations.
- Under Group, choose **Group by**, then **Group using** where present. **Sort groups** controls group order independently of row sorting. Read the rendered heading and the rows under that boundary.
- Change layout without changing the property to verify its shared semantics and layout-specific controls. Select rows to inspect supported bulk editors.

## Driving it with Playwright

Preconditions: a healthy, fresh controlled fixture. Reuse existing specs/page objects for supported paths; use a live browser for uncovered method combinations. Do not create another skill-owned spec suite.

1. Through **Settings → Group**, choose Score. Set **Group using → Every 100**, close settings, and expand both group headings. Require Alpha and Omega in `score:0` and Empty in `score:null`. Record `view.plugin_grouping_method.change` and the rendered interval heading.
2. Set **Every 1**, then **Sort groups → High→low**. Require group order `score:90`, `score:10`, `score:null`, and `view.group_sort.change`. This verifies group order, separately from a Score row-sort journey.
3. Switch Group by to Complete. Require checked/empty membership, no Group using selector, and only Manual under Sort groups. Switch to Tags: Alpha and Omega share Frontend, with no separate Backend group for Omega.
4. On a fresh page, use the Tags header's **Calculate → Count → Values**, **Unique**, and **Not empty**; require 3, 2, and 2. In the Score and Due headers, the **Calculate** submenu has a second **Calculate** category: select **Sum** and **Date range** respectively; require 100 and 4 days. Filter Score Greater than 50: require only Omega, sum 90, and date range 0 days. Clear the filter and require original totals.
5. Group by Created and inspect Relative/Day/Week/Month/Year. Choose Month and require one January 2025 group containing three rows. Switch to Timeline and inspect Timeline by: Due is eligible, Created/Edited are absent, while Created month grouping persists.
6. Retain actual menu actions, group boundaries, screenshots, and read-only resource diagnostics. Existing cell-editor, sorting, grouping, calculation, bulk-edit, and layout cases provide complementary evidence; running them alone does not prove all 12 plugins' combinations.

## Gotchas

- A direction label is not enough to establish ordering. Checkbox false is treated as empty and therefore stays last even for the Unchecked→checked label; assert actual row order.
- Grouping/sorting multi-select by its first option differs from filtering all selected operands and counting all tokens. Include a row with at least two options when verifying these distinctions.
- Generated times are read-only cell values, but still participate in organizing data. New/duplicated rows receive fresh timestamps; ordinary edits advance last-edited time. Adding a row to a historical timestamp group cannot assign that group's time.
- Group add/move copies a representative member's raw value, not a generated bucket label; a multi-select group can copy trailing tags. Verify interval/date/alphabetical movement with the selected grouping method instead of extrapolating from a Status-group drag. See [row actions](selection-and-row-actions.md).
- A method visible in source is source-mapped, not automatically browser-verified. Custom plugin registration, alternative method collections, and owner rejection require a suitable consumer. Keep observed paths distinct from the full capability matrix.
