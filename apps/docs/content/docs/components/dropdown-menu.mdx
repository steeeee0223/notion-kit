## Anatomy

```
<DropdownMenu>
  <DropdownMenuTrigger />
  <DropdownMenuContent>
    <DropdownMenuGroup>
      <DropdownMenuLabel />
      <DropdownMenuItem />
      <DropdownMenuItem />
    </DropdownMenuGroup>
    <DropdownMenuSeparator />
    <DropdownMenuRadioGroup>
      <DropdownMenuRadioItem />
      <DropdownMenuRadioItem />
    </DropdownMenuRadioGroup>
    <DropdownMenuSeparator />
    <DropdownMenuSub>
      <DropdownMenuSubTrigger />
      <DropdownMenuContent>
        <DropdownMenuGroup>
          <DropdownMenuItem />
        </DropdownMenuGroup>
      </DropdownMenuContent>
    </DropdownMenuSub>
  </DropdownMenuContent>
</DropdownMenu>
```

## Examples

---

### Default

A dropdown menu with groups, shortcuts, submenus, and a warning item.

<RegistryStory name="dropdown-menu" />

```tsx
<DropdownMenu>
  <DropdownMenuTrigger render={<Button>Open</Button>} />
  <DropdownMenuContent>
    <DropdownMenuGroup>
      <DropdownMenuLabel title="Account" />
      <DropdownMenuItem label="Profile">
        <DropdownMenuShortcut>⇧⌘P</DropdownMenuShortcut>
      </DropdownMenuItem>
    </DropdownMenuGroup>
  </DropdownMenuContent>
</DropdownMenu>
```

### Filtering

Wrap the owning dropdown root or searchable submenu in `DropdownMenuFilter`. Place the input outside `DropdownMenuList`, which contains the groups and actions. The list defaults to `max-h-75 overflow-x-hidden overflow-y-auto`. Add `className` only when the menu requires different styling.

<RegistryStory name="dropdown-menu-filter" />

```tsx
<DropdownMenuFilter>
  <DropdownMenu>
    <DropdownMenuTrigger render={<Button>Open</Button>} />
    <DropdownMenuContent>
      <DropdownMenuInput
        aria-label="Search actions"
        placeholder="Search actions..."
      />
      <DropdownMenuEmpty>No matches found.</DropdownMenuEmpty>
      <DropdownMenuList>
        <DropdownMenuGroup>
          <DropdownMenuItem label="Profile" />
          <DropdownMenuItem label="Settings" />
        </DropdownMenuGroup>
      </DropdownMenuList>
    </DropdownMenuContent>
  </DropdownMenu>
</DropdownMenuFilter>
```

`DropdownMenuFilter` forwards Base UI FilterProvider props and uses its defaults. Prefer uncontrolled query state. Pass `value` and `onValueChange` when the query also drives application behavior. Use `filter={null}` when the application renders its own matching rows.

Keep each label inside its `DropdownMenuGroup`. Filtering automatically hides a group and its label when none of its items match. Clearing the search restores them.

`DropdownMenuInput` includes native clearing and displays no search icon. Give the input a fixed accessible name.

Base UI renders a filtered popup as a dialog, its input as a searchbox, and its list as a menu. Let the library own these roles and keyboard behavior. The same provider and content work under `ContextMenu`; wrap each searchable submenu in its own provider.

### Checkbox Items

Use `DropdownMenuCheckboxItem` for toggling options on and off.

<RegistryStory name="dropdown-menu-checkbox" />

```tsx
<DropdownMenu>
  <DropdownMenuTrigger render={<Button>Open</Button>} />
  <DropdownMenuContent>
    <DropdownMenuGroup>
      <DropdownMenuLabel title="Appearance" />
      <DropdownMenuCheckboxItem
        checked={showStatusBar}
        onCheckedChange={setShowStatusBar}
        label="Status Bar"
      />
    </DropdownMenuGroup>
  </DropdownMenuContent>
</DropdownMenu>
```

### Radio Items

Use `DropdownMenuRadioGroup` and `DropdownMenuRadioItem` for mutually exclusive options.

<RegistryStory name="dropdown-menu-radio" />

```tsx
<DropdownMenu>
  <DropdownMenuTrigger render={<Button>Open</Button>} />
  <DropdownMenuContent>
    <DropdownMenuRadioGroup value={position} onValueChange={setPosition}>
      <DropdownMenuLabel title="Position" />
      <DropdownMenuRadioItem value="top" label="Top" />
      <DropdownMenuRadioItem value="bottom" label="Bottom" />
      <DropdownMenuRadioItem value="right" label="Right" />
    </DropdownMenuRadioGroup>
  </DropdownMenuContent>
</DropdownMenu>
```
